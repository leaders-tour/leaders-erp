# Phase 2 Planning — T02 일정요소

**목표:** 원본 목록 + 등록/상세 + 세트 편집의 수직 슬라이스. 수식·문구 엔진은 골격만.

## 1. 목표·범위·비범위

- In: T02-01 원본 목록, T02-02 등록·상세, T02-02A 유형 골격, T02-03 세트(중첩·순환 차단)
- Out: 실측·성과(T02-07), AI 문구·운영 기본 수식 하드코딩(D01/D02)

## 2. 화면/스토리

| 코드 | 이번 Phase | 비고 |
|------|------------|------|
| T02-01 | 필수 | 원본 관리. 사용본 탭=`미연동` |
| T02-02 | 필수 | 등록·상세 |
| T02-02A | 필수(스키마) | 유형별 입력 골격 |
| T02-03 | 필수 | 세트 중첩, 순환 참조 차단, 배치 ID=`CatalogElementItem.id` |
| T02-04~08 | 골격만 | 저장 훅 + `미정` UI |
| T02-07 | deferred | 실측·성과 |

스토리:

1. 단일 요소를 유형과 함께 등록한다.
2. 세트를 만들고 하위 요소/세트를 배치한다. 각 배치는 별도 ID.
3. 자기 자신(직간접)을 포함하면 저장이 거부된다.
4. 목록은 원본 최신 버전 1행이다.
5. 사용본 조회는 `미연동`이다 (고객 빌더 전).

## 3. 데이터·API 변경

- `CatalogElement` / `CatalogElementItem` 유지
- `updateCatalogElement`, `addCatalogElementSetItem`, `removeCatalogElementSetItem`
- 순환 검증: 서비스에서 ancestor walk
- 초기 유형: 기존 enum `MEETING | TRANSFER | MEAL | EXPERIENCE | MIXED` + T02-02A 확장 여지는 `kind` 문자 필드로 열지 않고, 추가 유형은 후속 enum ADD
- 버전: 수정 시 `version` increment. 옛 행 overwrite(1차). 스냅샷 테이블은 deferred

출발 파일: `DatasetElementsPage.tsx`, catalog module, `catalog.schema.ts`

## 4. UI 구조

- 목록: 원본/사용본 탭, 단일/세트 필터, 세트 펼침
- 상세 오버레이: 기본정보·유형 골격·세트 구성·문구/값/조건 탭(골격)
- 세트 편집: 검색 후 멤버 추가
